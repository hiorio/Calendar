# TimeFlower 앱 보강 점검 — 2026-09-05

## 범위와 읽는 법

현재 작업 트리의 화면·일정/반복 계산·인증·공유·첨부·알림 워커·위젯·마이그레이션·검증
구성을 함께 검토했습니다. 기존 미커밋 변경도 현재 동작에 포함했습니다. 최초 점검에서는

대형 위젯은 별도로 **지원되는 H/VStack 기반의 6주 전체 월간 달력**으로 보강했습니다.
iOS 17 이상에서는 위젯 컨테이너 폭에 맞추며, 중형은 현재 주·소형은 오늘 표시를 유지합니다.
기존 커밋에는 설치된 expo-widgets의 네이티브 렌더러가 지원하지 않는 Grid가 있었고,
스택 기반 변경은 작업 트리에만 있었습니다. 사용자가 보고한 기기의 정확한 설치 빌드는
확인하지 않았으므로 이 사실만으로 실기기 원인을 전부 확정하지는 않습니다.

검증 명령은 `lint`, `typecheck`, `test:unit`, `test:regression`, `web:export`입니다.
새 회귀 검사는 실제 소스와 Expo 직렬화 결과를 실행하되 DB·권한·네이티브 외부 경계는
모의합니다. V01은 해당 경계 테스트를 추가했고, V02는 호스팅 CI의 DB reset/smoke/SQL
회귀 및 기존 Mac mini 검사에 회귀 실행을 추가했습니다. **CI 파일 작성은 CI 통과와 다릅니다.**

남은 검증/적용 경계:

- Docker Desktop이 inference socket 오류로 시작되지 않아 전체 `db:reset`·`db:smoke`는
  아직 실행 검증하지 못했습니다. 공장 초기화 등 사용자의 Docker 데이터 삭제는 하지 않습니다.
- 임베디드 PostgreSQL 검사는 보조 검증일 뿐 실제 GoTrue·PostgREST·Storage 통합을 대신하지 않습니다.
- 위젯 및 추가된 `expo-network`의 Xcode/기기 검증은 원격 작업 브랜치의 Mac mini workflow가
  필요합니다. 변경은 미커밋 상태이며 commit/push·OTA·서버 배포·TestFlight는 하지 않았습니다.
- 사용자 요청에 따라 웹 직접 클릭 검증은 하지 않았습니다. V03의 APNs/FCM 수신·기기 간
  동기화·위젯 실제 표시·푸시 자격증명 확인은 계속 남습니다.
- 기존 잘못된 반복 종료값은 새 마이그레이션과 워커 적용 후 재계산됩니다. 경로 기록조차
  사라진 과거 고아 파일을 추측하여 지우지는 않습니다.
- F01~F05는 별도 제품 기능 제안으로 남겨두었습니다.

단정하거나 기존 검증 결과를 무시하고 21개 네이티브 패키지를 일괄 교체하지 않았습니다.
별도 SDK 57 패치 정렬과 Mac mini 회귀 검증이 남습니다. Sentry 조직/프로젝트 미설정
경고도 있으므로 번들 통과가 운영 오류 수집 연결을 보장하지 않습니다.

- **실행 확인**: 실제 계산 함수 또는 실제 소스를 메모리에서 실행해 재현했습니다.
  모의 DB를 사용한 검사는 운영 DB·푸시 전송 성공을 뜻하지 않습니다.
- **코드 확인**: 관련 호출과 최신 마이그레이션을 대조해 발생 경로를 확인했습니다.
  실제 계정 전환·기기 간 조작·운영 DB 공격 재현은 하지 않았습니다.
- **보강 제안/검증 공백**: 현재 오류로 단정하지 않고 별도로 표시합니다.

P1은 데이터 손실·권한 경계 또는 핵심 일정 누락 때문에 다음 배포 전에 우선 다룰
항목입니다. P2는 특정 조건에서의 오류·복구 실패·사용성 문제입니다. 정적 검사와
현재 테스트의 통과만으로 아래 문제가 없다고 판단하면 안 됩니다.

## P1 — 우선 수정할 항목

### A01. 후속 회차에서 전체 수정하면 과거 반복 일정이 사라짐 — 코드 확인

- 근거: `src/app/event-edit.tsx:131`, `:142`, `src/features/events/event-form.tsx:81`.
- 조건: 1월에 시작한 반복 일정의 9월 회차를 열고 제목만 바꾼 뒤 `전체` 저장.
  폼은 선택 회차의 시작일을 유지하므로 마스터 시작일도 9월로 옮겨집니다.
- 조치: 전체 수정은 마스터 기준 값을 사용하고, 범위 전환 시 폼의 의미와 날짜를
  재설정해야 합니다. 기존 예외의 보존/재배치 규칙도 함께 정해야 합니다.
- 완료 기준: 제목만 전체 수정했을 때 과거·미래의 모든 회차 날짜가 유지됩니다.

### A02. 긴 유한 반복은 400번째 회차 이후 조회에서 누락 — 실행 확인

- 근거: `src/lib/recurrence.ts:317`, `src/features/events/queries.ts:90`.
- 사례: 2026-01-01~2027-12-31 매일 반복의 `rrule_until`이 **2027-02-04**로 계산됩니다.
  화면 전개용 400회 제한을 시리즈 종료 계산에도 사용하기 때문입니다.
- 조치: 종료 계산을 화면 제한과 분리하고, 기존에 잘못 저장된 종료값도 재계산합니다.
- 완료 기준: 400회 이상 COUNT/UNTIL 반복의 마지막 회차가 조회·리마인더 후보에 남습니다.

### A03. 한 회차의 종일 전환이 월간 화면에서 깨짐 — 실행 확인

- 근거: `src/features/events/queries.ts:104`, `src/lib/recurrence.ts:266`.
- 조건: 시간 지정 반복 회차 하나를 종일로 바꿈. 월간 예외 SELECT에 `is_all_day`가 없어
  `is_all_day=false`, `start_at=null`인 잘못된 조합이 만들어집니다. 날짜 계산 결과가
  **1970-01-01**이 되어 선택 날짜에서 사라지는 사례를 재현했습니다.
- 조치: 예외 SELECT와 타입을 일치시키고 종일/시간 컬럼 모양을 함께 검사합니다.
- 완료 기준: 종일↔시간 지정 전환이 월간·날짜 상세·위젯에서 일치합니다.

### A04. 다른 날짜·시간으로 옮긴 회차가 달력과 알림에서 누락 — 실행 확인

- 근거: `src/features/events/queries.ts:112`, `src/lib/recurrence.ts:253`,
  `supabase/functions/notification-worker/index.ts:139`,
  `supabase/migrations/20260727000200_notification_delivery.sql:141`.
- 사례: 1월 회차를 3월로 옮겨도 3월 목록에 나타나지 않습니다. 09시 회차를 12시로
  옮긴 뒤 12시 리마인더 시간창을 전개해도 결과가 `[]`였습니다.
- 원인: 원래 회차를 현재 시간창에서 먼저 찾고 예외를 덮어, 시간창 밖에서 들어온
  수정 회차를 만들 수 없습니다. 마스터 종료 범위 밖 이동도 같은 문제가 있습니다.
- 조치: 예외의 변경된 날짜·시간으로 후보를 별도 조회하고 `original_start`로 병합합니다.

### A05. 알림 재시도가 이전 계정·탈퇴한 구성원에게 갈 수 있음 — 코드 확인

- 근거: `supabase/functions/notification-worker/index.ts:431`, `:455`, `:465`.
- 조건: 첫 발송 실패로 PENDING delivery 생성 → 로그아웃/토큰 소유권 이전 또는
  캘린더 탈퇴·강퇴 → 재시도. 이미 저장한 delivery의 토큰과 현재 수신 권한을 대조하지 않습니다.
- 조치: 실제 발송 직전에 토큰 소유자·활성 상태·현재 멤버십을 확인하고 부적합 항목을
  종료합니다. 큐 생성 뒤 음소거한 경우의 발송 정책도 명시적으로 적용합니다.
- 완료 기준: A→B 계정 전환과 강퇴 뒤 A의 미발송 내용을 새 세션/전 구성원이 받지 않습니다.
  실제 APNs/FCM 재현은 별도 검증 대상입니다.

### A06. 삭제된 캘린더에 옛 초대 링크로 재가입 가능 — 코드 확인

- 근거: `supabase/migrations/20260726000800_invites.sql:62`, `:99`, `:107`,
  `20260726000200_membership_rules.sql:135`, `20260726000300_rls.sql:182`.
- 조건: 마지막 구성원이 떠나 soft delete된 캘린더의 유효한 초대를 수락.
  preview/accept는 `calendars.deleted_at`을 보지 않고, 일정 RLS는 멤버십만 확인합니다.
- 결과: 기존 링크 보유자가 다시 구성원이 되어 삭제된 캘린더의 과거 일정에 접근할 수 있습니다.
- 조치: preview·accept·하위 접근 헬퍼에서 활성 캘린더를 확인하고 삭제 시 초대를 폐기합니다.
  새 마이그레이션과 비구성원·삭제 상태 DB 스모크가 필요합니다.

## 오류 수정과 구분할 제품 보강 제안

### 의존성 후속 점검 — 호환 패치 반영, 경고 일부 남음

`npm audit --omit=dev`의 high 5개는 image-size/Metro 경로의 전파 집계였습니다.
Expo 57과 RN 0.86의 기존 선언 범위를 유지하며 `@expo/metro 56.0.2`, Metro 전체
`0.84.5`로 잠금 파일을 정렬하고 취약 image-size 경로를 없앴습니다. Metro의
[공식 0.84.5 변경 기록](https://github.com/react/metro/releases/tag/v0.84.5)이 이 수정 경로를
설명합니다. xmldom도 각각 허용 범위인 `0.8.15`/`0.9.12`로 갱신했습니다.
직접 Metro 의존성·강제 override·Expo 다운그레이드는 추가하지 않았습니다.

최종 감사 결과는 **high 0, moderate 18**입니다. 남은 경고도 18개의 독립 결함을
뜻하지는 않으며 URL 디코더와 uuid/xcode 경로에서 상위 패키지로 전파된 항목이 있습니다.
`decode-uri-component` 수정판은 ESM 전환과 기존 query-string의 버전/호출 계약이
맞지 않아 단순 override하지 않았습니다. 이 URL 처리 경로는 Expo 호환 패치/백포트와
딥링크 회귀 검증이 추가로 필요합니다. uuid 공지의 영향 API(v3/v5/v6 외부 buffer)는
현재 xcode가 호출하는 인자 없는 v4와 다르므로 경고 제거만을 위한 major 교체는 하지 않습니다.
근거: [디코더 공지](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr),
[uuid 영향 API](https://github.com/advisories/GHSA-w5hq-g745-h8pq).
