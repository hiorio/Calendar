# 외부 캘린더 연동 계획

## 현재 구현 범위

현재 버전은 iOS 시스템 캘린더를 읽기 전용으로 연결한다.

- 설정에서 `기기 캘린더 연결`을 누를 때만 iOS 전체 접근 권한을 요청한다.
- 기기에 등록된 iCloud, Google, Exchange, 구독 캘린더를 목록으로 보여 준다.
- 연결 직후 발견한 캘린더를 표시하고, 이후 캘린더별 토글로 표시 여부를 바꾼다.
- 선택한 외부 일정은 월간 화면과 날짜 상세에 합쳐서 표시한다.
- 외부 일정을 누르면 iOS의 원본 일정 화면을 연다.
- 외부 일정은 Supabase에 업로드하지 않고 다른 TimeLine 구성원에게 공유하지 않는다.
- 연결 해제는 TimeLine의 선택만 지우며 원본 일정과 iOS 권한을 변경하지 않는다.
- 웹에는 기기 캘린더 API가 없으므로 안내만 표시한다.

이 범위는 현재 바이너리에 이미 포함된 `expo-calendar`와 캘린더 권한 문구를 사용한다.

## 서비스별 가능 범위

| 서비스 | 현재 | 후속 직접 연결 | 공유 캘린더로 노출 |
|---|---|---|---|
| Apple/iCloud | iOS 시스템 캘린더에서 읽기 | 별도 REST 연동은 계획하지 않음 | iCloud 원본 공유 또는 서버 동기화 필요 |
| Google Calendar | iPhone에 등록돼 있으면 읽기 | Google OAuth + Calendar API | 서버 프록시/캐시 방식으로 가능 |
| 네이버 캘린더 | iOS에 CalDAV로 등록된 경우에만 보일 수 있음 | 공개 Calendar OAuth/API가 확인되기 전까지 제외 | 공식 API 또는 제휴 없이는 제외 |

네이버 아이디·비밀번호나 앱 비밀번호를 TimeLine이 직접 받는 방식과 비공식 API 사용은
보안 및 서비스 지속성 문제 때문에 구현하지 않는다.

## 후속 1: Google Calendar 직접 연결

기기 설정과 무관하게 Google 계정 선택만으로 연결하려면 다음 작업이 필요하다.

1. Google Cloud 프로젝트와 Calendar API 활성화
2. OAuth 동의 화면, 개인정보처리방침, 리디렉션 URI 등록
3. 최소 권한인 Calendar 읽기 전용 scope 요청
4. Supabase Edge Function에서 OAuth code 교환
5. refresh token 암호화 저장 및 연결 해제 시 폐기
6. calendar list 조회와 사용자의 표시 캘린더 선택
7. 최초 전체 동기화 후 `syncToken` 기반 증분 동기화
8. 만료·권한 철회·410 응답 시 재연결 또는 전체 동기화
9. Google 공개 앱 검증과 스토어 개인정보 항목 갱신

일반 Google 로그인은 이메일·프로필 권한일 뿐 Calendar 읽기 권한이 아니다. 앱 로그인과
`Google Calendar 연결`은 별도의 명시적 동의 과정으로 유지한다.

## 후속 2: 연결된 Google 캘린더를 TimeLine 구성원과 공유

사용자가 일정을 하나씩 복사하지 않아도 되도록 `공유 외부 캘린더` 연결을 추가한다.

Supabase에는 원본 일정 전체보다 먼저 다음 연결 메타데이터를 둔다.

- 연결 소유자
- provider와 provider calendar id
- 보여 줄 TimeLine 공유 캘린더
- 읽기 전용 여부
- 동기화 기간
- 마지막 동기화 상태
- 암호화된 provider token 참조

구성원의 조회 요청은 Edge Function이 RLS와 같은 멤버십 검사를 한 뒤 Google에서 읽거나
짧은 수명의 캐시를 반환한다. provider token은 절대로 클라이언트나 다른 구성원에게
전달하지 않는다.

초기 공유 정책은 다음과 같이 제한한다.

- 외부 원본은 연결자만 관리한다.
- 다른 구성원은 읽기 전용이다.
- 비공개 일정은 `제목 공개` 또는 `바쁨만 공개`를 연결자가 선택한다.
- 연결 해제 시 캐시를 삭제하고 즉시 구성원에게서 숨긴다.
- 일정 내용 변경·삭제·반복·타임존을 원본 기준으로 갱신한다.

## 후속 3: Apple 캘린더 공유

EventKit 데이터는 사용자의 기기에만 있으므로 서버가 다른 구성원 대신 실시간 조회할 수
없다. 다음 두 선택지 중 하나가 필요하다.

1. 사용자가 iCloud 캘린더 자체를 Apple 기능으로 공유하고, 각 구성원이 자기 기기에서
   TimeLine 접근을 허용한다.
2. 연결자의 앱이 일정 내용을 Supabase에 동기화해 공유용 읽기 전용 미러를 만든다.

두 번째 방식은 앱이 열릴 때는 동기화할 수 있지만 iOS 백그라운드 실행은 보장되지 않는다.
따라서 Google과 같은 실시간 서버 동기화로 표현하지 않고 마지막 동기화 시각을 명확히
보여 줘야 한다.

## 구현 우선순위

1. 현재 기기 캘린더 읽기 전용 기능을 TestFlight에서 권한·반복·종일·시간대별로 검증
2. Google Calendar 직접 연결
3. Google 공유 외부 캘린더와 `바쁨만 공개`
4. 필요성이 확인되면 Apple 공유 미러
5. 네이버는 공식 API 또는 제휴 경로가 생길 때 재검토
